Parte 3

Esercizio finale: la classe Personaggio

Testo

Si vuole rappresentare in Java il personaggio di un videogioco. Scrivere la classe Personaggio con i seguenti attributi privati:

  • iniziale: la lettera iniziale del nome;
  • livello: numero intero compreso tra 1 e 100;
  • puntiVita: numero intero, al massimo 5 000;
  • esperienza: punti accumulati, che possono superare i 5 miliardi;
  • velocita: numero con parte decimale (ad esempio 1.5);
  • haScudo: indica se il personaggio possiede uno scudo.

La classe deve avere i seguenti costruttori:

  1. Personaggio(): iniziale '?', livello 1, puntiVita 100, esperienza 0, velocita 1.0, haScudo false;
  2. Personaggio(char iniziale): come il precedente, ma con l'iniziale indicata;
  3. Personaggio(char iniziale, int livello, boolean haScudo), con queste regole:
    • se il livello è minore di 1 diventa 1; se è maggiore di 100 diventa 100;
    • puntiVita = livello × 50;
    • esperienza = livello × 1000;
    • velocita = 1.0 + livello / 10, calcolata con la parte decimale (livello 15 → 2.5).

Richieste

  1. Per ciascun attributo indicare il tipo primitivo più adatto, motivando la scelta.
  2. Scrivere la classe con gli attributi e i tre costruttori.
  3. Indicare il valore di tutti gli attributi dopo ciascuna delle seguenti istruzioni: 
    Personaggio p1 = new Personaggio();
Personaggio p2 = new Personaggio('Z', 150, true);
Personaggio p3 = new Personaggio('A', -5, false);
  4. Se nel costruttore c) la velocità fosse calcolata con this.velocita = 1.0 + livello / 10;, quale valore si otterrebbe per il livello 15? Perché?
  5. Se i punti vita fossero calcolati con this.puntiVita = (short) (livello * 500);, quale valore si otterrebbe per il livello 70? Perché?
  6. Quali delle seguenti istruzioni compilano? Motivare la risposta. 
    new Personaggio('L', 5);
new Personaggio('L', 5.5, true);
new Personaggio('L', 'A', true);
new Personaggio(true);
  7. Perché nel costruttore c) il parametro livello è di tipo int e non byte, come l'attributo?
  8. (Facoltativo) Aggiungere l'attributo forza di tipo float e un costruttore con quattro parametri che riutilizzi il costruttore c) tramite this(...).

Soluzioni

Soluzione 1: scelta dei tipi
AttributoTipoMotivazione
inizialecharun singolo carattere
livellobyte1–100 rientra nell'intervallo −128 … 127 (accettabili anche short o int)
puntiVitashort5 000 rientra nel massimo di 32 767; un byte non basta (accettabile anche int)
esperienzalongun int arriva a circa 2,1 miliardi
velocitadoublenumero con parte decimale (accettabile anche float)
haScudobooleandue soli valori: vero o falso
Soluzione 2: la classe 
public class Personaggio {
    private char iniziale;
    private byte livello;
    private short puntiVita;
    private long esperienza;
    private double velocita;
    private boolean haScudo;

    // a) costruttore senza parametri
    public Personaggio() {
        iniziale = '?';
        livello = 1;
        puntiVita = 100;
        esperienza = 0;
        velocita = 1.0;
        haScudo = false;
    }

    // b) costruttore con l'iniziale
    public Personaggio(char iniziale) {
        this.iniziale = iniziale;
        livello = 1;
        puntiVita = 100;
        esperienza = 0;
        velocita = 1.0;
        haScudo = false;
    }

    // c) costruttore completo
    public Personaggio(char iniziale, int livello, boolean haScudo) {
        if (livello < 1) {
            livello = 1;
        }
        if (livello > 100) {
            livello = 100;
        }
        this.iniziale = iniziale;
        this.livello = (byte) livello;             // da int a byte: serve il cast
        this.puntiVita = (short) (livello * 50);   // da int a short: serve il cast
        this.esperienza = livello * 1000L;
        this.velocita = 1.0 + livello / 10.0;      // 10.0: divisione con parte decimale
        this.haScudo = haScudo;
    }
}

Il costruttore b) può anche riutilizzare il costruttore a), evitando di ripetere le assegnazioni:

public Personaggio(char iniziale) {
    this();                     // deve essere la prima istruzione
    this.iniziale = iniziale;
}
Soluzione 3: valori degli attributi

In p2 il livello 150 viene ridotto a 100, in p3 il livello −5 viene portato a 1; i calcoli successivi usano il livello già corretto.

Soluzione 4: divisione intera
Si ottiene 2.0 invece di 2.5. livello / 10 è una divisione tra due int: 15 / 10 vale 1 e la parte decimale viene scartata; poi 1.0 + 1 = 2.0. Per ottenere 2.5 bisogna dividere per 10.0.
Soluzione 5: overflow
Si ottiene −30536. 70 × 500 = 35 000 supera il massimo di uno short (32 767): il cast fa ripartire il valore dal minimo, quindi 35 000 − 65 536 = −30 536. Il cast fa compilare il codice ma non controlla che il valore sia rappresentabile.
Soluzione 6: istruzioni che compilano
  • new Personaggio('L', 5): non compila, non esiste un costruttore con parametri (char, int).
  • new Personaggio('L', 5.5, true): non compila, la conversione da double a int richiede un cast.
  • new Personaggio('L', 'A', true): compila, la conversione da char a int è automatica; il livello vale 65.
  • new Personaggio(true): non compila, non esiste un costruttore con un solo parametro boolean.
Soluzione 7: tipo del parametro
I numeri interi scritti nel codice sono di tipo int. Con un parametro byte l'istruzione new Personaggio('L', 50, true) non compilerebbe: servirebbe (byte) 50 a ogni chiamata. Accettando un int, il valore viene controllato e convertito una sola volta, all'interno del costruttore.
Soluzione 8: attributo forza 
private float forza;

public Personaggio(char iniziale, int livello, boolean haScudo, float forza) {
    this(iniziale, livello, haScudo);   // riutilizza il costruttore c)
    this.forza = forza;
}

// esempio: Personaggio p = new Personaggio('R', 30, true, 7.5f);

Il suffisso f in 7.5f è necessario: senza, il letterale sarebbe un double.
